# Qwen Image 2.1 移植 GR308：从单卡出图到 TP2 与分块 VAE

Qwen Image 2.1 的 GR308 实验经历了三次目标变化：先让完整链路真正生成图片，再把解码阶段压下来，最后把 DiT 的计算拆到两个逻辑芯片。三步分别解决兼容性、阶段瓶颈和计算并行，不能用一个总加速比抹平中间发生的变化。

本文以 2026-09-21 主目录测试记录和 09-22 独立工作树报告为依据，补充对应 Codex 工作区最后的算子定位。10 月 2 日只整理既有证据，没有重跑 GPU 实验。最新工作区仍在探索原生 SDPA，没有完成新的融合注意力验收。

## 第一阶段：把模型框架与设备后端接起来

最初环境包含四张物理卡、八个逻辑设备；单个可见逻辑设备约 55.48 GiB。PyTorch 是 2.7.1+cpu，设备能力通过 torch_fant 插件提供，配合 FTUCA、FHCCL 和厂商扩展。Diffusers 固定在当时的 0.41 开发版提交 `9f1246971270…`，模型权重约 30.9 GiB。

这类移植不能只替换 `cuda` 字符串。Python 层调用成功，下面可能落到通用分解，也可能走设备专用内核；设备名称能够被识别，也不代表框架涉及的全部张量操作都有对应实现。项目首先沿着真实出图路径逐项排除不支持的操作。

RoPE 原实现涉及复数路径，适配中改为在 CPU 准备实数 cos/sin 查找表，再在 FANT 上做实数旋转。缓存 tuple 的切片、`repeat_interleave`、高维布局转换和 pixel shuffle 也分别处理：索引可以先在 CPU 构造，再通过 `index_select` 取值；超过后端适用范围的八维 permute 拆成较低维的步骤；pixel shuffle 用切片与拷贝表达。

这些替换的目的首先是保存张量语义。输出 shape 相同还不够，head 顺序、位置索引、轴排列和最终像素位置必须一致。某个操作的替代写法也可能更慢，所以兼容层需要留下清晰入口，便于在端到端基线成立后再定位热点。

模型组件的生命周期是第二个问题。让 DiT 与 VAE 同时驻留时，已占用约 47.45 GiB 后再申请约 5.06 GiB 会失败。项目改为分阶段执行：先完成去噪并保存 latent，再让 VAE 解码。这样增加了阶段切换，却让两个大组件不必同时占据设备内存。

## 单卡基线：真正出图以后再计时

1024 分辨率、40 步、BF16 的单卡记录中，DiT 耗时 1622.44 秒，平均每步约 40.56 秒，峰值 37.81 GiB；独立 VAE 解码耗时 1241.47 秒，峰值 30.15 GiB。两段相加为 2863.92 秒，约 47 分 44 秒，已有实际 PNG。

这是阶段耗时之和，不应自动包含模型下载、冷加载、进程启动和所有 CPU 后处理。4 步 smoke 的 DiT 约 162.6 秒，也能走通路径，但图像质量不足，不能用它替代 40 步成品的质量验证。低步数实验的用途是缩短工程迭代时间。

| 阶段 | 40 步单卡记录 | 可以确认的事情 |
| --- | ---: | --- |
| DiT 去噪 | 1622.44 s | 真实模型、目标分辨率的计算链路完成 |
| 独立 VAE | 1241.47 s | latent 能被解码并落成 PNG |
| 两阶段求和 | 2863.92 s | 阶段计算成本基线，不是完整冷启动响应时间 |

VAE 在总计算时间中占了很大部分。继续只优化 DiT，即使把它减半，剩余 VAE 仍会占据主要等待。因此下一步先调整解码路径，再比较多芯执行。

## 第二阶段：用阶段接口隔离运行时差异

工作树中的适配器没有把整个 vLLM-Omni CUDA 路径直接搬过来，而是复用 Diffusers 与 FANT，围绕四个阶段接口组织流程：`prepare_encode`、`denoise_step`、`step_scheduler`、`post_decode`。这样编码、每步模型计算、调度器状态更新和最终解码可以分别测量。

这一结构对验证很有帮助。同一 latent 可以交给不同 VAE 路径；同一初始噪声和时间步可以交给单卡、流水线或 TP2 DiT；scheduler 的输入输出则保持独立。否则 loader、scheduler、dtype 与通信拓扑同时变化，很难解释图片差异来自哪一层。

通信能力也先单独探测。在同一物理卡的两个逻辑芯片间，64 MiB BF16 AllReduce 约 2.68 ms，对应报告口径约 25 GB/s bus bandwidth；AllGather 约 3.91 ms，聚合口径约 34.3 GB/s。这里两个 bandwidth 定义不同，不能直接据数值判定哪个原语“更快”。`all_to_all_base` 当时不支持，意味着依赖该能力的 Ulysses 路径不能直接启用。

工程选择由已验证的原语约束。一个并行算法理论上适合模型，不代表目标后端已经提供其通信基础。项目因此分别探索分块 VAE、按层流水线和真正的张量并行，避免把一种方案失败误写成多卡完全不可用。

## 分块 VAE：主要收益先来自算法路径

VAE 的优化先把大图拆成 tile。1024 分辨率的记录使用 36 个 tile；双芯时每芯处理 18 个。为了隔离变量，报告比较了单卡整体解码、单卡串行分块和双芯分块，而不是只给出首尾两个数字。

| VAE 路径 | 耗时 | 相对关系 |
| --- | ---: | --- |
| 旧单卡整体解码 | 1241.47 s | 原阶段基线 |
| 单卡串行分块 | 154.70 s | 更换解码组织后大幅降低耗时 |
| 双芯分块 | 143.50 s | 相对串行分块再降低约 7.2% |

从 1241.47 到 143.50 的变化同时包含分块方式和设备数，不能叫作“双卡带来 8.65 倍加速”。严格分辨后，主要收益发生在分块路径；加第二个芯片只带来额外约 7.2% 的阶段延迟下降。tile 调度、尾块与合并成本都会影响并行效率。

分块还改变了内存需求。串行分块峰值约 39.64 GiB；双芯记录分别约 17.4 / 23.0 GiB。跨芯不均衡说明显存占用除了 tile 数，还受缓存、临时张量和各阶段驻留影响，不能按任务一半就假设内存完全相等。

数值方面，报告记录图像 MAE 0.0435/255，99.9815% 的通道差异不超过 1，最大差异 11。平均误差很小，最大差异仍要保留。这个结果支持当前样本的分块实现，尚不是各种构图、尺寸和随机种子下都没有接缝的证明。

## 按层流水线：容量收益成立，延迟收益没有成立

DiT 首先尝试把 32 层分成 16+16。前半在一芯片，后半在另一芯片，阶段之间传递激活。直接 P2P 路径遇到 `palRbTree` 断言，实验因此采用 CPU 中转，而没有把不稳定的传输留在默认路径。

512 分辨率、2 步的 DiT 从 9.28 变为 9.73 秒；1024、4 步从 163.33 变为 164.07 秒，后者约慢 0.45%。峰值从约 40.595 GB 降到 32.889 GB，约减少 19%，latent 完全一致。

这个结果并不矛盾。单个样本先经过前 16 层，再经过后 16 层；在没有足够微批填满流水线时，两段并没有同时为同一个样本计算。CPU 中转还增加等待。因此该方案的实际成果是分散权重和显存压力，保留正确性，而不是降低当前单样本延迟。

如果未来要把它用于吞吐服务，需要另外设计微批、缓冲区和阶段调度，测量填充、稳态与排空阶段。当前报告没有完成那种服务测试，不能把潜在吞吐并行写成已获得收益。

## 真正的 TP2：切分每一层的计算

随后实现的 TP2 进入了每个 DiT block。每 rank 保留 16 个 attention head，QKV、gate 和部分投影沿输出方向切分；attention 输出与 MLP 输出沿输入方向切分，再汇总局部结果。32 层中每层有两次 AllReduce。

与 16+16 流水线相比，TP2 让两个芯片参与同一层，缩短这一步的计算量，但需要支付每层通信。权重从单卡约 14.230 GB 降到每 rank 约 7.250 GB，没有严格减半是因为还存在复制模块和非切分状态。

| DiT 条件 | 单卡 | TP2 | 比例 |
| --- | ---: | ---: | ---: |
| 512，2 步 | 9.28 s | 5.51 s | 1.68× |
| 1024，4 步 | 163.33 s | 89.60 s | 1.82× |

1024 短测中每 rank 峰值约 29.495 GB。两个 rank 的 latent 相同，但与未分片单卡基线并非逐位一致：512 的 MAE 0.00921、最大差 0.203125；1024 的 MAE 0.00575、最大差 0.09375，均为有限值。并行归约顺序变化后，需要把这种误差带入后续图像质量验收。

按 4 步平均耗时估算，40 步 DiT 约 896 秒，再加 143.5 秒 VAE，约 1040 秒、17.3 分钟。**这只是投影，报告没有完成 TP2 的 40 步端到端出图计时。** 不能把这个数字与早期实测 47 分 44 秒直接配成“已实现的完整生成加速”。

## 剩余瓶颈：名字叫 SDPA，实际走哪条路径

TP2 block0、sequence length 4096 的分解中，SDPA 约 0.485–0.489 秒；按 32 层粗略外推，占约 22.4 秒 step 的七成。GEMM 约 0.0195 秒，norm 与布局操作约 0.085–0.088 秒。AllReduce 调用的墙钟还可能包含等待前序计算，不能把它全部归因于链路。

独立 32 MiB AllReduce 约 1.57 ms；按每层两次估算，一步约 0.1 秒，只占当前 step 的约 0.45%。这个拆解说明，在该形状下优先缩短 SDPA 比继续争论通信峰值更有依据。不过缺少 DRAM 等硬件计数器，仍不能直接断定 SDPA 已经带宽饱和或计算饱和。

后续工作区确认的调用链是 Diffusers → PyTorch `scaled_dot_product_attention` → 通用 math decomposition → torch_fant 的 bmm/mm/softmax，而不是已经注册的 FANT fused SDPA。强制选择 FLASH 或 EFFICIENT 标志，测试仍落到近似相同的约 484 ms；显式 math 路径约 569 ms，反而增加 17.6%。Python 层选项名不能代替底层 dispatch 证据。

在线 softmax 分块候选也没自动胜出。sequence 1024 的 Python 组合路径约 76–85 ms，对照约 34.7 ms，慢了 2.2–2.4 倍；4096 尚未完成对应测试。公式减少中间存储，并不保证由很多小算子拼出的实现比后端大算子快。原生 FTUCA SDPA 仍在开发调查中，本文不提供尚不存在的性能结果。

## 小算子融合：单点很快，整块提升更小

厂商扩展 `vllm_fant._custom_ops` 接到 iFormer 算子后，RMSNorm 从 11.69 降到 0.615 ms，RoPE 从 24.69 降到约 0.62–0.64 ms，SiLU 从 8.83 降到 0.679 ms。但把 SiLU 放回包含投影和布局的 MLP 片段后，仅 9.35→9.21 ms，不足 2%，因此没有仅凭单点倍率保留它。

组合到真实 block 的结果是 0.67934→0.63190 秒，下降 6.98%。误差 MAE 0.00360、最大值 2；相对未分片参考的 MAE 从 0.00394 变为 0.00412。有限值和平均误差不能遮住最大值，最终仍需要完整图像验证。

候选已接入 TP2 路径，但由 `ENABLE_FANT_OPERATORS=1` 显式控制，默认关闭。它通过的是当前 block 的性能与误差门，还没有完成完整 40 步生成质量与稳定性验收。保留一个可回退的候选入口，比提前宣布全链优化完成更有工程价值。

## 用阶段数据重建一次请求的成本

从这些结果可以重建优化的实际顺序，而不需要虚构一条已经跑完的最终服务。第一阶段的观测单位是“一个完整模型组件”：先确认编码后的 latent 可以进入 DiT，DiT 输出可以进入独立 VAE，最后能落成图片。只有这条链成立，后面的计时才有对象。

第二阶段的观测单位是“相同输入下的替代路径”。VAE 复用同一 latent，把整体解码与分块解码比较；DiT 固定分辨率、步数与初始状态，把未分片、按层流水线和张量并行比较。这样，某一路径变快时，至少可以知道它有没有同时改输入问题。

第三阶段再下钻到一个 block。此时才比较 SDPA、投影、归一化、布局转换和 collective。单 block 的结果不能直接替代完整 step，因为不同层、首次缓存建立与 scheduler 开销可能不同。报告使用“按三十二层外推”的说法，恰好保留了实测与估算之间的距离。

这些数据也解释了一个表面上的反差：RMSNorm 和 RoPE 的单点倍率远大于 TP2，最终对整块的作用却只有几个百分点。原因不是单点数字失效，而是它们只占一部分执行时间。即使把一个占总耗时百分之十的模块彻底消除，其余百分之九十仍然存在；若融合又增加布局处理，实际收益还会更小。

同样，通信 microbenchmark 与 block 里的通信调用不能直接相减。独立探针在输入已准备好时启动；真实层中的 collective 可能等待前序 kernel 或其他 rank。两者之间的差异包含依赖与同步，只有进一步加时间线证据，才能分清链路传输和迟到的生产者。

当前记录因此留下了三种可复用制品：能够复现输入的阶段接口、记录各候选实际路径的参数，以及同时保存平均和最大误差的比较结果。后续如果换驱动或算子扩展，可以先重新比较这些制品，再决定是否重跑昂贵的完整生成。这里没有声称已经完成自动化生产回归系统，只说明现有工程接口为何便于继续验证。

## 这次实现留下了什么

项目形成了可运行的单卡出图基线、按阶段组织的适配器、分块 VAE、两种跨芯 DiT 方案，以及能定位到真实 dispatch 的算子剖析。每个结果回答的问题不同：分块 VAE 改变主要阶段耗时，流水线降低容量压力，TP2 在短测中取得计算加速，小算子融合则进一步减少 block 开销。

当前最值得继续验证的是 TP2 完整 40 步出图，以及原生 SDPA 是否能在固定 shape、正确性和数值门下胜过通用分解。已有记录足以说明实现过程和短测效果，却还不支持把全部候选默认打开并称为稳定服务。

资料来自《Qwen Image 2.1 GR308 Test》（2026-09-21）、独立工作树《Qwen Image 2.1 Omni FANT Test》（09-22）与对应算子调查工作区。公开的模型框架入口可参考 [Diffusers](https://github.com/huggingface/diffusers)。本文所有 GR308 数值均来自本地历史实验，不代表 Diffusers 上游的性能声明。

继续实验时还需固定计时是否包含首次缓存建立。首次执行可能分配缓冲区、构建位置编码或初始化通信；稳定步骤则复用这些状态。若一个候选记录首轮、另一个只记录暖运行，比较就会把生命周期成本误归给计算实现。当前文章保持每份报告原有的阶段范围，没有把这些未对齐成本强行补成统一总延迟。
