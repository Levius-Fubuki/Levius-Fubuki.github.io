Reading FlashAttention-4: Non-Matmul Bottlenecks, Online Softmax, and Pipelines

Published2026-10-02|Updated2026-10-02|AI Infra

Reading FlashAttention-4: Non-Matmul Bottlenecks, Online Softmax, and Pipelines

本文由既有深读笔记整理入博客，并核对了对应 Codex 学习工作区。内容区分论文事实、教学推导与实验边界；论文中的性能与规模数据属于作者报告，不是我在本地复现的成绩。原笔记的公式、示例和推导在此保留。

01 / Executive summary

一页读懂：论文主张与结论

结论：FA4 的核心不是让 Tensor Core 单独跑得更快，而是让 softmax、片上存储和调度跟上 Blackwell 已翻倍的矩阵吞吐。

论文事实Blackwell 的矩阵乘加（MMA）能力增长快于特殊函数和共享内存能力，FA4 因而同时重构前向流水线、指数计算、反向 CTA 协作与任务调度。主文在 B200 上报告 BF16 attention 最高 1613 TFLOP/s，约为峰值的 71%；相对 cuDNN 9.13 为 1.1–1.3×，相对 Triton 为 2.1–2.7×。总体主张见论文 §1，设计见 §3，编译方法见 §4，评测见 §5。

阅读主线。把 attention 看成多个资源同时推进的生产线：MMA 是主装配线，MUFU 负责指数，SMEM/TMA 负责周转，warpgroup 与 CTA 调度决定谁等待谁。优化目标是缩短最长的那一段，而非只提高某一条指令的峰值。

工程推断最可迁移的思想是“关联式摘要（associative summary）+ 有结构的调度”：先把分块结果压成可合并状态，再按硬件依赖安排执行；这不等价于一个能表达所有算子的通用 runtime semiring。

局限论文未给出端到端训练收敛、能耗、p95/p99 延迟或广泛形状覆盖，因此这些吞吐结果不能直接外推为所有模型、部署和后续软件版本上的普遍优势。

02 / Computation map

Attention 计算与数据流地图

结论：标准 attention 是“相似度 → 概率 → 加权汇总”；FlashAttention 的分块算法在精确算术中与标准公式等价，但浮点舍入和快速指数近似会带来数值差异。

一句话定义与公式

论文事实QKᵀ 计算每个 query 与每个 key 的相似度分数；softmax 把一行分数变为和为 1 的归一化权重；PV 再用这些权重汇总 value。缩放 attention 为：

S = QKᵀ / √d
P = softmax(S)
O = PV

直觉类比，随后是精确定义

像顾客先给仓库中的每件商品打相关度分数，再把分数换成预算占比，最后按占比装货。准确地说：每行 S 属于一个 query，softmax 沿 key 维归一化，输出向量是同一行概率对 V 各行的线性组合。

小数值例子

若一个 query 对两个 key 的分数为 [0, ln 3]，softmax 权重为 [1/4, 3/4]；对应 value 为 [8, 20] 时，输出是 1/4×8 + 3/4×20 = 17。

反向为何有 5 次 MMA

论文事实反向不保存完整分数矩阵，而是重算并依次完成五个矩阵乘：重算 S=QKᵀ；dP=dO Vᵀ；dV=Pᵀ dO；经 softmax 导数得到 dS 后，dQ=dS K、dK=dSᵀ Q。这解释了反向比前向更重，也解释了 TMEM 不可能同时容纳五块累加器。

局限这里省略 mask、dropout、缩放常数和数值格式细节，目的是建立数据依赖；具体 kernel 仍需按 causal/varlen 等模式处理边界。attention 背景见论文 §2.1，反向见 §3.2。

03 / Hardware glossary

Blackwell GPU 术语速查

结论：理解 FA4 的最低硬件门槛，是分清计算单元、存储层级、搬运引擎与协作线程组织。

论文事实把 GPU 想成多层仓库与车间很有帮助，但类比后必须落回硬件定义：

术语的类比与准确含义
术语 直觉类比 准确硬件定义
thread 一名工人的执行档案 一个 lane 的执行上下文，拥有私有寄存器状态；线程被组成 warp 执行。
SM 容纳多个班组的车间 Streaming Multiprocessor，调度驻留的 warp/CTA，并包含 register file、SMEM、Tensor Core 等执行与存储资源。
warp 32 人同步班组 32 个以 lockstep 方式执行同一指令的线程，是 SIMT 调度基本单位。
CTA / thread block 共享一间车间的班组集合 可共享 SMEM、在同一个 SM 上驻留并协作同步的线程块。
warpgroup 四个相邻班组组成的专职工段 4 个相邻 warp（128 线程）的组合，可为 TMA、MMA 或 softmax 等工作专职化。
HBM / L2 厂外大仓 / 厂区缓存 HBM 是高容量高延迟显存；L2 是跨 SM 共享的片上缓存。
SMEM 车间周转区 CTA 显式管理的片上 shared memory，容量有限但延迟低。
register / RMEM 工人手边托盘 线程寄存器及论文中的 register-memory 路径，用于标量和局部状态，受容量与 occupancy 约束。
TMEM 张量装配线旁的专用工位 Blackwell tensor memory；异步 MMA 可把累加器写入其中，从而开放新的合法依赖与消费顺序，不只是“多一块存储”。
DSMEM 相邻车间的共享传送口 CTA cluster 内可跨 CTA 访问的 distributed shared memory。
TMA 自动叉车 Tensor Memory Accelerator，异步搬运多维张量，减少线程参与的数据移动。
MMA / MUFU 矩阵装配机 / 特殊函数机 MMA 执行矩阵乘加；MUFU 执行 exp2 等特殊函数，吞吐资源独立。
CTA cluster 可互通的车间组 一组可进行 cluster 级同步并通过 DSMEM 交换数据的 CTA。

工程推断FA4 中的“快”来自这些资源的生命周期相互咬合：TMA 预取下一块、MMA 生产 TMEM 累加器、softmax warpgroup 消费当前块。单独数 FLOP 无法预测流水线是否堵塞。

局限这些术语是面向本文的数据流解释，不替代 Blackwell ISA 与编程指南。见论文 §2.2。

04 / Roofline shift

硬件非对称扩展与瓶颈迁移

结论：在 128×128 tile 上，前向的 MMA 与指数都需 1024 周期；MMA 再快也会被 MUFU 或 SMEM 封顶。

论文事实论文用简化的多资源 roofline 比较每个 tile 的理想周期。取 M=N=d=128：

展开 / 收起完整推导
Forward MMA:
T_MMA = 4MNd / 8192
= 4×128×128×128 / 8192
= 1024 cycles

Forward EXP:
T_EXP = MN / 16
= 128×128 / 16
= 1024 cycles

Forward SMEM:
T_SMEM = 6MN / 128
= 6×128×128 / 128
= 768 cycles

SMEM 的 6MN 是论文的简化流量计数：把相关 tile 阶段折算为每个元素共 6 byte 的片上读写，再除以假定的 128 byte/cycle；它不是对真实 bank conflict、指令发射或所有临时量的逐条仿真。

Backward MMA (5 MMAs, multiply-add counted as 2 FLOPs):
T_MMA = 10MNd / 8192
= 10×128×128×128 / 8192
= 2560 cycles

Backward SMEM, 1-CTA:
T_SMEM = 26×128 = 3328 cycles

Backward SMEM, 2-CTA:
T_SMEM = 21×128 = 2688 cycles

Backward EXP:
T_EXP = MN / 16 = 128×128 / 16 = 1024 cycles

后两条 26×128 与 21×128 是论文按 tile 数据流汇总后的简化 SMEM 项；2-CTA 通过各自只 staging 半个 B 操作数等设计，减少了每 CTA 的 SMEM 周期。

局限这是简化的多资源 roofline，未纳入寄存器/RMEM 压力、L2 命中、调度空洞、同步与依赖延迟。它能定位候选瓶颈，不能当成实测运行时间。

工程推断Blackwell 把 MMA 吞吐约翻倍，而 MUFU/SMEM 没有同比扩展，所以 non-MMA work 从配角变为关键路径。见论文 §2.2、表 1。

05 / Forward pipeline

前向流水线的阶段重构

结论：前向用 128×128 tile、TMEM 与 ping-pong 阶段把矩阵计算、softmax 修正和搬运重叠起来。

论文事实Blackwell 的异步 MMA 将累加器写入 TMEM。对一个 128×128 score tile，MMA warpgroup 生产 QKᵀ，softmax warpgroup 归约观测到的行最大值与指数和；只有维护的 softmax 锚点被实际推进时，correction warpgroup 才修正旧输出——通常是新旧最大值之差换算到 base-2 域后超过阈值，而不是每次观测到更大行最大值都修正。TMA 同时预取后续 K/V；两套缓冲 ping-pong，当前块被消费时下一块已在路上。见论文 §3.1.2；conditional rescale 见 §3.1.4。

小例子：两块交替

阶段 A 对 K/V block 0 做 MMA 时，阶段 B 预取 block 1；A 的结果进入 TMEM 后，softmax 组读取它，MMA 组转而处理 block 1。若 block 1 只把观测最大值小幅提高但未跨阈值，旧锚点继续使用，不触发 correction；只有累计的 base-2-scaled increase 超过阈值并推进锚点时，correction 组才对旧累加输出乘统一修正因子。

工程推断TMEM 的真正价值是提供新的合法依赖图：MMA 不必把完整累加器留在线程寄存器里，消费者可在明确同步后从 TMEM 取数，生产与归约更易重叠。把它概括为“容量更大”会漏掉这一点。

局限阶段数增加会带来 barrier、容量和 occupancy 取舍；若 tile 形状或序列太小，填充/排空成本可能抵消重叠收益。

06 / Numerical state

Online Softmax 的状态更新

结论：online softmax 保存运行最大值 m、指数质量 ℓ 与加权载荷 u；只要三者使用同一锚点缩放，精确算术中的 u/ℓ 不变。

论文事实标准 online softmax 对到目前为止的分数 sᵢ 与 payload vᵢ，维护 m=max sᵢ、ℓ=Σexp(sᵢ−m)、u=Σexp(sᵢ−m)vᵢ，最终 O=u/ℓ。FA4 的 conditional rescale 另外允许维护锚点暂时落后于观测最大值；只有锚点实际推进时，旧的 ℓ 与 u 才乘同一个修正因子。

展开 / 收起完整推导

完整数值例子

Block A：scores [2,4]、payload [10,20]；Block B：scores [5,3]、payload [30,40]。

以最终最大值 m=5 为标准锚点：

ℓ = exp(-3)+exp(-1)+1+exp(-2) ≈ 1.5530
u = 10exp(-3)+20exp(-1)+30+40exp(-2) ≈ 43.2688
O = u/ℓ ≈ 27.86

若暂时沿用旧锚点 m=4：

old-anchor mass = exp(-2)+1+exp(1)+exp(-1) ≈ 4.2215
old-anchor payload = 10exp(-2)+20+30exp(1)+40exp(-1) ≈ 117.61
output = payload/mass ≈ 27.86

两套质量和载荷相差共同因子 e，所以精确算术中比值不变；这个例子说明“旧锚点仍可保持比值”，不代表每次最大值从 4 变到 5 都要推进锚点。若分数已是自然指数域，增量 1 换成 base-2 域约为 log₂(e)=1.443，低于典型阈值 8，因而不会触发这次 correction。浮点舍入、溢出与下溢仍会使实现结果不同，不能宣称“浮点中没有近似”。

论文事实论文 §3.1.4 对 BF16 取 base-2 阈值 τ=8，意味着延迟修正期间临时比例最多可到 2⁸=256。

代码事实论文公式写 eˣ，实现机制使用 exp2，先乘 scale_log2 把自然指数域换到以 2 为底的域；阈值单位必须与所在域一致。可对照 softmax.py。

局限阈值是实现的性能—数值折中，不是任意输入范围下的误差证明。见论文 §3.1.4。

07 / Exp emulation

指数函数的软件模拟

结论：FA4 只把约 10–25% 的 exp2 转移到 FMA 多项式路径，以缓解 MUFU 拥堵，同时保留硬件 exp2 作为主体。

论文事实软件路径将输入拆为整数部分 n 与小数部分 f；数学分解是 2ˣ = 2ⁿ · 2ᶠ，即两部分在数学上相乘。小数部分用 Horner 形式的多项式在 FMA 上近似；论文的具体实现并非必须发射一次普通浮点乘，而是通过移位构造 exponent bits，并把多项式结果的 mantissa bits 组合进 FP32 表示。调度器只让约 10–25% 元素走这条路，其余仍用 MUFU.EX2，把工作分摊到不同执行资源。见论文 §3.1.3。

小例子

对 x=3.25，先写成整数 3 与小数 0.25；数学上是 2³ · 2^0.25，具体实现则沿用上述 exponent/mantissa bits 组合，而不要求一次普通浮点乘。Horner 形式减少多项式求值的中间乘法并利用 FMA 吞吐。

局限这些误差来自在 [0,1) 内随机采样的 400 万个输入、以 FP64 为 reference 的局部比较，不是完整 attention 误差界，更不是端到端训练收敛证明；混合比例也依赖资源与形状。

08 / Backward design

反向 2-CTA 协作设计

结论：2-CTA 反向用 cluster 内协作换取更少的单 CTA SMEM 流量，但同步、DSMEM 与原子归约让它高度 Blackwell 特化。

论文事实反向包含前述 5 次 MMA；TMEM 区域按生命周期复用，因为无法同时容纳五个 accumulator tile。反向流水线见论文 §3.2.2。2-CTA 配置取 M=256,N=K=128，两个 CTA 各 staging 操作数 B 的一半，并通过 DSMEM 交换半块 dS。

per-CTA dQ:
(M/2, 2N) × (2N, d) → (M/2, d)
代入 M=256, N=d=128:
(128, 256) × (256, 128) → (128, 128)

每个 CTA 的 dQ 工作扩大 N 方向覆盖，最终全局 dQ atomic add 次数减半。可以把两个 CTA 类比为相邻车间：各自存半套原料，通过内部传送口交换半成品；精确定义是 cluster 内 DSMEM 通信与同步，不是 CPU 式共享地址空间。

工程推断TMEM aliasing 的原则是按“最后一次读取”回收区域，而非按变量名永久占位；这是 pipeline resource planning 的典型实例。

局限2-CTA 方案依赖 Blackwell 的 TMEM、DSMEM 与 cluster 能力，不能无改动移植到旧架构。见论文 §3.2.3。

09 / Scheduling

Warp 专职化与任务调度

结论：内核内用 warpgroup 专职化隐藏资源延迟，内核间用确定性归约与长任务优先减少尾部空转。

确定性归约

论文事实atomic add 的到达顺序不固定，浮点非结合性使结果 nondeterministic。semaphore 可固定归约顺序，但会增加 fence 与 stall。论文对 causal 情形用排序/最短处理时间（SPT）思路安排顺序，使第一笔 dQ 写入不必等待前序；确定性实现速度最高约为 NONDETERMINISTIC 1-CTA backward 的 75%，不能误读为达到最快 2-CTA 实现的 75%。见论文 §3.2.4。

跨任务 LPT

小例子：任务 [8,7,3,2]

两台等速“工位”采用 short-first 升序列表调度时，按 2、3、7、8 依次分配给当前负载较小的工位：负载从 2/3 变为 9/3，最后成为 9/11，makespan 为 11。Longest Processing Time first（LPT）则先派 8 和 7，再把 3、2 放到当前负载更小的工位，负载成为 10 与 10，makespan 为 10。LPT 让最长任务更早启动，把本例中最后完成的尾部从 11 缩到 10；该例解释原则，不声称所有原顺序都更差。

论文事实真实 attention scheduler 不是盲目全局排序：它保留 batch 外层顺序，配合 head swizzle 维护 L2 locality；variable-length 场景可预处理并排序 metadata。H200 上 LPT 对 MHA 提升 4–8%，对 MQA8 提升 7–14%。见论文 §3.3。

CuTe-DSL 编译

论文事实CuTe-DSL 是 Python embedded DSL，lower 到 PTX 再生成 SASS。单个 kernel 的编译对比中，FA3 为 55s/45s，FA4 为 2.5s/1.4s，即 22×/32×；这是单 kernel 编译，不是整个工程构建时间。见论文 §4；代码入口见 FlashAttention CuTe 目录。

局限调度收益取决于任务长度分布、cache 行为和 launch 组织；均匀工作负载下可优化空间更小。调度见论文 §3.3，编译方法见 §4。

10 / Evaluation

实验结果与性能边界

结论：FA4 在论文所测 B200 BF16 区间表现强，但版本、形状与测量口径限定了结论外推范围。

论文事实主文实验采用 BF16，序列长度 1K–32K，总 token 固定为 32K；head dimension 测 64、128，以及 QK/V 维为 (192,128) 的组合。主文与图中设备写 B200。结果为 1.1–1.3× cuDNN 9.13、2.1–2.7× Triton，峰值 1613 TFLOP/s，约 71% theoretical peak。见论文 §5、Figures 4–7；局限与后续讨论见 §6。

论文事实论文也注明更新的 cuDNN 已吸收相关技术并达到相似性能，因此“最高 1.3×”不能被宣传为对当前所有 cuDNN 版本的普遍领先。

11 / Reusable patterns

可迁移的算子设计模式

结论：FA4 可抽象为四类可复用设计对象；以下均是本文工程归纳，不是作者提出的正式 API。

StableWeightedReduce

工程推断非作者 API。状态为 running max、mass 与 weighted payload，提供可结合的 block merge；可用于 dense、sparse、ragged、split-K 和 distributed merge。

NonMmaBalancePolicy

工程推断非作者 API。根据 MUFU/FMA 压力、误差预算和数据格式，决定 hardware exp 与 polynomial/FMA 路径的比例。

PipelineResourcePlan

工程推断非作者 API。显式描述 RMEM、SMEM、TMEM 的生命周期、aliasing、producer/consumer barrier 与 pipeline stages。

ReductionSchedule

工程推断非作者 API。在 atomic 与 deterministic reduction、LPT/SPT 次序、CTA-pair/cluster 协作之间选择。

组合例子

一个 ragged split-K attention 可先用 StableWeightedReduce 合并分片摘要，再由 ReductionSchedule 决定固定顺序或原子累加；同时用 PipelineResourcePlan 验证中间状态是否能安全复用。

工程推断这也回应侧栏的核心想法：可复用 kernel 往往来自“关联式摘要 + 结构化调度”，而不是强行把任意算子塞进一个 universal runtime semiring。

局限四个名称是教学抽象，尚无类型系统、代价模型或跨架构验证，不能当作已实现框架。
